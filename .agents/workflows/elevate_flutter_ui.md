When the user invokes `/elevate_flutter_ui`, read `.agents/agents.md`,
`.agents/skills/weathergpt_delivery.md`, and
`.agents/skills/flutter_ui_excellence.md`.

Audit and improve the Flutter experience in `vaanilaiai/lib/`. Work without
ordinary review gates and keep iterating through the following loop:

1. Refresh `.agents/UI_AUDIT.md` with evidence for home, map, chat, alerts,
   advisories, climate, search, settings, and authentication screens.
2. Select one highest-impact visual, usability, accessibility, responsive, or
   dark-theme issue.
3. Implement an original, reusable Flutter solution; keep data-source labels
   truthful and preserve existing working behavior.
4. Test light/dark mode, narrow/wide screens, text scaling, loading/error
   states, and relevant widget/static checks.
5. Log the outcome in `UI_AUDIT.md` and `PROGRESS.md`, then start the next
   improvement.

Do not copy other weather apps' protected branding or assets. Do not add a UI
feature that claims live radar, satellite, IMD, INCOIS, or lightning data unless
the real backend source exists. Stop only for exhausted budget/quota, a required
external asset/license/credential decision, unsafe destructive work, or when
the UI audit has no remaining material issue.
